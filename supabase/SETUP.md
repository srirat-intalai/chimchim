# ตั้งค่า Supabase สำหรับ ChimChim

## ขั้นตอน

1. สมัคร/ล็อกอิน [supabase.com](https://supabase.com) แล้วกด **New Project** (แผนฟรีพอสำหรับช่วงเริ่มต้น)
2. รอโปรเจกต์สร้างเสร็จ (ประมาณ 1-2 นาที)
3. ไปที่ **SQL Editor** → **New query** → คัดลอกไฟล์ [schema.sql](schema.sql) ทั้งไฟล์วางแล้วกด **Run**
   - รันรอบเดียวจบตอนตั้งโปรเจกต์ใหม่ (ครอบคลุมทั้ง Phase 1: โปรไฟล์/ร้าน/โพสต์/รีวิว/follow/like, Phase 2:
     ระบบรายงาน/analytics, Phase 3: sync bio/รูปโปรไฟล์ + แก้ posts ให้ผูกกับร้านแทนเพจเก่า, Phase 4:
     แก้ไข/ลบรีวิว + ลบร้าน, Phase 5: seed ร้านตั้งต้น 11 ร้านเข้า Supabase จริง)
   - **ถ้าโปรเจกต์เคยรันไฟล์นี้ไปแล้วรอบหนึ่ง** (เช่นมาอัปเดตทีหลัง) ห้ามรันทั้งไฟล์ซ้ำ เพราะ `create table` ของ
     Phase 1/2 จะ error ทันที (ตารางมีอยู่แล้ว) แล้วทำให้ Phase ใหม่ ๆ ท้ายไฟล์ไม่ถูกรันไปด้วย — ให้คัดลอกเฉพาะ
     บล็อกของ Phase ที่ยังไม่เคยรัน (มีคอมเมนต์ `-- Phase N` คั่นไว้ชัดเจน) ไปรันแยกแทน
4. ไปที่ **Project Settings → API** คัดลอก 2 ค่านี้เก็บไว้:
   - **Project URL** (เช่น `https://xxxxx.supabase.co`)
   - **anon public key** (คีย์ยาว ๆ ขึ้นต้นด้วย `eyJ...`)
5. เอา 2 ค่านั้นมาบอก Claude เพื่อเชื่อมเข้ากับเว็บ (จะใส่ในไฟล์ config ฝั่ง frontend — **ใช้ได้แค่ anon key เท่านั้น ห้ามเอา `service_role` key มาใช้ฝั่ง frontend เด็ดขาด** เพราะมันข้าม RLS ได้หมด ถ้าหลุดไปอยู่ในโค้ดหน้าเว็บใครก็เอาไปลบ/แก้ข้อมูลทุกคนได้)

## หลังเชื่อมต่อแล้วต้องทำอะไรต่อ

ข้อมูลเดิมที่เคยอยู่ใน `localStorage` (บัญชีผู้ใช้, ร้านที่โพสต์, รีวิว, โพสต์, ไลก์/follow) **จะไม่ย้ายเข้า Supabase ให้อัตโนมัติ** เพราะอยู่คนละเบราว์เซอร์กันไปหมด — เท่ากับเริ่มฐานข้อมูลใหม่ ไม่ใช่ปัญหาถ้ายังเป็นช่วงทดสอบ/เดโม แต่ถ้ามีข้อมูลจริงที่อยากเก็บไว้ (เช่นร้านที่โพสต์ไปแล้ว) ต้องพิมพ์ใหม่หลังย้ายระบบ

## เกณฑ์ auto-hide เนื้อหาที่โดนรายงาน

ตั้งไว้ที่ 3 รายงานขึ้นไปต่อโพสต์/ร้าน 1 ชิ้น จะถูกซ่อนออกจากฟีดอัตโนมัติ (ดูใน `schema.sql` ฟังก์ชัน `check_report_threshold()`) ปรับตัวเลขได้ถ้าต้องการ

## ดูรายงานที่เข้ามา (สำหรับแอดมิน)

ตาราง `moderation_reports` เป็น insert-only ตาม RLS โดยตั้งใจ (ใครก็รายงานได้ แต่อ่านรายงานของคนอื่นผ่าน
เว็บแอปปกติไม่ได้เลย แม้แต่เจ้าของแอปเอง) ต้องดูผ่านสคริปต์แยกที่รันในเครื่องเท่านั้น (ใช้ secret key —
**ห้ามเอา secret key ไปใส่ในโค้ดฝั่ง frontend เด็ดขาด**):

1. เปิดไฟล์ `.env` (ไฟล์เดียวกับที่มี `GEMINI_API_KEY`) เพิ่ม:
   ```
   SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
   SUPABASE_SECRET_KEY=sb_secret_xxxxxxxxxxxxxxxxxxxx
   ```
   (เอา secret key จาก Project Settings → API Keys → "secret" — คนละอันกับ anon/publishable key ที่ใช้ฝั่งเว็บ)
2. รัน `npm run admin:reports` — จะสรุปให้ว่าเนื้อหาไหนโดนรายงานกี่ครั้ง ด้วยเหตุผลอะไรบ้าง และถูกซ่อนอัตโนมัติไปแล้วหรือยัง
